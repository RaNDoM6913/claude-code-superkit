# Changelog

All notable changes to claude-code-superkit are documented here.

## [Unreleased]

- **Installer and updater fixed (crosscheck B01–B04 plus three issues found while fixing them):**
  - **Merge keeps your settings (B01):** "Merge — skip existing" (and `--defaults`) used to overwrite `.claude/settings.json` with package defaults, dropping user hooks, permissions, env and plugins. Merge now uses the existing file as the base, only adds missing superkit hooks (deduplicated per event and matcher), plugins and keys, never changes an existing value or the user's `permissions`, writes a timestamped `settings.json.bak-<ts>` first, skips the write when nothing changes and leaves invalid JSON untouched with a warning.
  - **Stack hooks fire on edits again:** `buildSettings` attached every stack/package hook (Go, TypeScript, ruff, cargo, frontend-ui, frontend-3d) to `PostToolUse[0]`, which has been the `Bash` group, so they never ran on Edit/Write. They now go to the group whose matcher covers Edit and Write (created if missing); a merge re-run adds them there and reports stale entries in the Bash group as removable.
  - **One ui-reviewer (B02):** the variant is chosen before copying (frontend-ui selected → umbrella). Merge refreshes a pristine older copy, upgrades a pristine core copy to the umbrella, never downgrades a pristine umbrella to core and keeps a customised copy with a conflict warning; the updater applies the same policy.
  - **Updater covers everything the installer installs (B03):** frontend-ui and frontend-3d packages listed in the meta stacks and the extras (including the red-blue-auditor scan.sh and patterns) are now synced under the pristine/preserve rule.
  - **`--profile` takes effect (B04):** the chosen profile is written to `env.CLAUDE_HOOK_PROFILE` in settings.json (merge keeps a value you set); the default is a valid profile already exported in the shell, else `standard`.
  - **No code from names:** `--stacks` / `--extras` must be known package names matching `^[a-z0-9][a-z0-9-]*$` (`--extras=skillsmp-search` is now an error instead of a no-op), and the updater parses `.claude/.superkit-meta` instead of `source`-ing it, ignoring invalid names.
  - Tests: npm suite 142 → 188 (new `test/installer-merge.test.js`, extended settings-builder tests), updater suite 34 → 74 checks. Live hook firing in a Claude session, the updater's network path and Windows are not verified.

- **Commands fixed (crosscheck B05, B06, B11, B12):** `/review` resolves and records BASE, HEAD and working-tree inclusion per target before anything else (PR mode takes files, hunks and the head SHA from the PR, never the local checkout), stops with `REVIEW NOT RUN` when a target cannot be resolved instead of reporting an empty diff as clean, passes the range to reviewers and validators, and names untracked/uncommitted files it did not review; `/review` and `/dev` Phase 12 now read reviewers' `Specialist follow-up:` lines and dispatch each installed, not-yet-run specialist once (one follow-up wave), listing the rest with a reason; `/lint` without `--fix` writes nothing (check-only format commands, `golangci-lint --fix=false`, `ruff check --no-fix`, `make fmt` only when check-only) and runs Go/Rust with local toolchain prefixes; diagnostic `npx` calls in `/lint`, the GAN agents and rubric and the writing-commands skill use `npx --no --`. ### Fixed (critical — macOS portability + hook output stream)

Two production bugs discovered in a real tgapp Claude Code session on 2026-04-18. Both hit macOS users with stock system `awk` (BWK 20200816, not gawk). One bug was already hot-patched in tgapp (commit `7d146bca`); this release upstreams that fix plus the companion stream-redirect bug.

- **`packages/core/hooks/dev-required-on-commit.sh`** — `cycles_last_hour()` used the gawk-only 3-argument `match($0, /regex/, array)` form. On BWK awk this is a syntax error, which crashes the hook, leaves the variable empty, and falls through to bash `[ "" -ge 2 ]` — evaluating as restrictive and firing a false BLOCK on commits. Replaced with POSIX 2-arg `match()` + `RSTART`/`RLENGTH`/`substr()` extraction. Portable across gawk, BWK (BSD/macOS), and mawk. *Hot-patched in tgapp commit `7d146bca` on 2026-04-18; upstreamed here.*

- **`packages/core/hooks/doc-check-on-commit.sh`** — error-output block wrote `BLOCKED: Required documentation not staged` and the `Missing docs:` list to **stdout**. Claude Code's hook runner only surfaces **stderr** to the user when a hook exits non-zero — stdout is discarded. Result: users saw the opaque `PreToolUse:Bash hook error: No stderr output` message with no actionable info, retried the same commit, got the same opaque error. All 11 `echo` statements in the MISSING branch (and the post-check advisories) now redirect to `>&2`.

- **`packages/core/hooks/loop-guard.sh`** — same stdout-instead-of-stderr antipattern. Both BLOCK branches (3+ identical-call detection, A→B→A→B alternation) had `echo` going to stdout — 14 lines total now redirect to `>&2`.

- **`packages/core/hooks/superkit-counts-verify.sh`** — same antipattern in the count/version mismatch BLOCK path. 15 echoes now redirect to `>&2` (not wired by default but fix applied for consistency when devs wire it manually).

### Added

A malicious `.claude/settings.json` committed to an untrusted repo can register a PreToolUse hook that runs arbitrary code the moment you open the project. The hook inspects git history on `.claude/settings.json`: if the last 10 commits contain any author other than your `git config user.email` within the last 7 days, it prints a loud stderr warning naming the offending commits and touches `${TMPDIR:-/tmp}/claude-untrusted-settings-<session>` so downstream hooks can downgrade decisions. Each line carries `{ts, session_id, project, event, tool, field, tag, counter, marker_exists, prev_hash, hash}` where `hash = sha256(prev_hash || canonical_json_of_line_without_hash)`. Genesis hash is 64 zeros. Tamper detection: recomputing the chain exposes the first divergence. Opt-out via `CLAUDE_DISABLE_AUDIT_TRAIL=1`.
