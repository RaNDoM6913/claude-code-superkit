# CS2 ELO Balance System — Gorilla Game League

> **Дата:** 2026-04-11 (обновлено)
> **Турнир:** Gorilla Game League (CS2, Беларусь)
> **Проблема:** Текущее ограничение "сумма ELO ≤ 12,500" позволяет сильный дисбаланс в команде
> **Цель:** Динамическая формула баланса — без дивизионов, без потолков/полов, для всех уровней

---

## Проблема

Текущее правило: сумма FACEIT ELO 5 лучших игроков ≤ 12,500.

Реальный пример дисбалансной команды:

| Игрок | FACEIT ELO |
|-------|-----------|
| ДИРЕКТОР (капитан) | 1,000 |
| ... | 3,265 |
| FAIZER | 3,607 |
| Q | 3,049 |
| PAJEROSPORT | 1,479 |
| **Сумма** | **12,400** |

Разброс: 2,607 ELO (1,000 → 3,607). Три игрока 3000+ доминируют, слабые — "балласт".

### Что делают платформы

| Платформа | Механизм | Лимит |
|-----------|----------|-------|
| FACEIT Super Match | Макс. разница ELO в пати | 400 ELO |
| FACEIT Premium (тест) | Макс. разница в пати | 800 ELO |
| FACEIT Level 10+ | Прогрессивные штрафы ELO | -25%/-75% при разнице >300 |
| Valve CS2 Premier | Макс. разница в 5-стеке | 10,000 ELO |
| Valorant Ranked | Макс. разница по рангам | 1 ранг для высоких |
| ESEA Open 1-8 | Макс. индивидуальный уровень | Level 8 FACEIT |
| Dota 2 Battle Cup | Тиеры по MMR | Команда по тиеру высшего |
| NHL (хоккей) | Жёсткий кэп + floor + 20% на игрока | Ceiling + 74% floor |
| NBA (баскетбол) | Мягкий кэп + luxury tax | Прогрессивные штрафы |

### Ключевые выводы

1. **Суммарный ELO кэп без доп. ограничений** — ни одна крупная платформа так НЕ делает
2. **Разница ELO между игроками** — стандарт индустрии (FACEIT: 400, Valve: 10,000)
3. **Пик ELO за 90 дней** — ESEA использует для защиты от деранка
4. **Минимум матчей** — стандарт (FACEIT: 50+, рекомендуемо: 100+)
5. **NHL-модель** самая подходящая: жёсткий потолок + floor-стоимость + лимит на звезду

## Отвергнутые подходы

### 1. Max Spread Cap (макс. разброс ≤ 1,800)
- Блокирует команды с большой разбежкой даже при низком суммарном ELO
- Отсекает легитимные составы: 4,000 + 1,000 + мостик не проходят

### 2. Standard Deviation Cap (σ ≤ 600)
- Сложно объяснить участникам, нужен калькулятор
- Те же проблемы с жёсткими порогами

### 3. Weighted ELO (×1.40 / ×1.20 / ×1.00)
- Коэффициенты кажутся произвольными
- Плохо калибруется, требует постоянной подстройки

### 4. Гибрид 3 правила (сумма + разброс ≤ 1,800 + макс. ≤ 3,200)
- **Жёсткий потолок 3,200** блокирует редких 4,000-4,500 игроков
- **Разброс 1,800** запрещает легитимные составы с новичками
- Нет гибкости — бинарное "да/нет" без динамики

### 5. Лестница (макс. шаг между соседями ≤ 700-1,000)
- С шагом 700: игрок 4,000+ не может собрать команду (минимальная лестница > 12,500)
- С шагом 1,000: слишком жёсткий для команд с низким суммарным ELO
- Блокирует составы вроде 3,500/3,000/2,500/500/500 (raw 10,000) — хотя они не представляют угрозы

## РЕКОМЕНДУЕМАЯ СИСТЕМА: Floor Cost + Динамические слоты

### Концепция: "Минимальная стоимость слота"

Вдохновлено NHL salary cap. Каждый игрок **"стоит"** не менее 1,500 ELO от командного бюджета, даже если его реальный рейтинг ниже. Хочешь взять слабого — он всё равно "съест" 1,500 из бюджета.

### Формула

```
cost(x) = max(x, 1500)
Σ cost(player_i) ≤ 12,500
```

**Два параметра:**
- `FLOOR = 1,500` — минимальная стоимость слота (FACEIT Level 4)
- `CAP = 12,500` — бюджет команды

**Ключевые свойства:**
- **Нет верхнего потолка** — игрок 4,000 или 4,500 ELO может играть
- **Нет нижнего порога** — игрок 500 или 100 ELO может играть
- **Слабый игрок = дорогой** — берёшь 500 ELO, он стоит 1,500 (штраф 1,000 из бюджета)
- **Чем слабее балласт — тем меньше бюджета на звёзд**

### Почему FLOOR = 1,500?

| Floor | Проблемная команда (12,400 raw) | Команда 3500/3000/2500/500/500 (10,000 raw) | Сбалансированная (12,500 raw) |
|-------|-------------------------------|---------------------------------------------|-------------------------------|
| 1,000 | 12,400 ✅ (не ловит!) | 11,000 ✅ | 12,500 ✅ |
| **1,200** | **12,600 ❌ (ловит)** | **11,400 ✅** | **12,500 ✅** |
| **1,500** | **12,921 ❌ (ловит)** | **12,000 ✅** | **12,500 ✅** |
| 2,000 | 13,400 ❌ | 13,000 ❌ (слишком строго) | 12,500 ✅ |

**1,500 оптимален:**
- Чётко ловит проблемную команду (запас 421 ELO)
- Не блокирует команды с низким суммарным
- 1,500 ELO = FACEIT Level 4, ниже — настоящие новички, логичный порог стоимости

## Динамический калькулятор слотов

Формула работает как **интерактивный конструктор** — после каждого добавленного игрока система пересчитывает доступный бюджет и допустимый диапазон для следующих.

### Формулы динамического расчёта

```
После добавления k игроков:

  spent = Σ cost(added_players)
  remaining = 12,500 − spent
  slots_left = 5 − k
  reserved = (slots_left − 1) × 1,500     ← минимум для оставшихся слотов
  max_next_elo = remaining − reserved      ← максимум для следующего игрока
  recommended = remaining ÷ slots_left     ← оптимальный ELO для баланса
```

## Формулировка для регламента

> **Правила формирования состава**
>
> Каждый игрок команды имеет **стоимость** = max(его FACEIT ELO, 1 500).
>
> Сумма стоимостей всех 5 игроков не должна превышать **12 500**.
>
> **Пример:** Игрок с ELO 800 "стоит" 1 500 (минимальная стоимость слота). Игрок с ELO 3 000 стоит 3 000 (своё ELO).
>
> Ограничений на индивидуальное ELO нет — могут играть как новички (500 ELO), так и про-уровень (4 000+ ELO), если команда вписывается в бюджет.
>
> ELO определяется как **максимальный рейтинг FACEIT за последние 90 дней** (защита от намеренного деранка).

### Простое объяснение для игроков

```
Каждый слот в команде стоит минимум 1,500.
Если твой ELO выше 1,500 — ты стоишь свой ELO.
Если ниже — ты всё равно стоишь 1,500.

Бюджет команды: 12,500.
Чем сильнее твоя звезда — тем скромнее остальные.
Чем слабее "балласт" — тем дороже он обходится.
```

## Онлайн-калькулятор (спецификация)

### Интерфейс

5 полей ввода (слоты). По мере заполнения:
- Показывается стоимость каждого игрока (ELO или 1,500 — что больше)
- Текущая потраченная сумма
- Оставшийся бюджет
- Максимально допустимый ELO для следующего слота
- Рекомендуемый ELO (оставшийся бюджет / оставшиеся слоты)
- Индикатор: ✅ проходит / ⚠ на границе / ❌ не проходит

### Функционал

```
Вход: 5 значений ELO (ввод по одному или все сразу)
Выход:
  - Стоимость каждого слота: max(ELO, 1500)
  - Суммарная стоимость
  - Статус: PASS / FAIL
  - Оставшийся бюджет после каждого слота
  - Диапазон для следующего слота
  - Рекомендация по оптимальному ELO
```

### Формула для калькулятора

```javascript
const FLOOR = 1500;
const CAP = 12500;

function cost(elo) {
  return Math.max(elo, FLOOR);
}

function validate(players) {
  const costs = players.map(cost);
  const total = costs.reduce((a, b) => a + b, 0);
  return {
    costs,
    total,
    pass: total <= CAP,
    remaining: CAP - total,
  };
}

function nextSlotRange(addedPlayers) {
  const spent = addedPlayers.map(cost).reduce((a, b) => a + b, 0);
  const remaining = CAP - spent;
  const slotsLeft = 5 - addedPlayers.length;
  const reserved = (slotsLeft - 1) * FLOOR;
  const maxNext = remaining - reserved;
  const recommended = remaining / slotsLeft;
  
  return {
    remaining,
    slotsLeft,
    maxElo: maxNext,
    recommended: Math.round(recommended),
    possible: maxNext >= FLOOR, // можно ли вообще добавить игрока
  };
}
```

## Дополнительные рекомендации

### Анти-смурф политика

Формула не спасает от смурфов — нужны отдельные меры:

1. **Минимум 100 матчей** на FACEIT за последние 6 месяцев
2. **Peak ELO за 90 дней** вместо текущего — защита от намеренного деранка
3. **Верификация аккаунта** — привязка к телефону / паспорту
4. **Возраст аккаунта** — минимум 3 месяца на FACEIT
5. **Report system** — подозрительных игроков проверяет организатор

### Пересмотр параметров

После первого сезона проанализировать:
- Сколько команд отклонено
- Средний effective cost прошедших команд
- Жалобы на дисбаланс в матчах
- Параметры для подстройки:
  - `FLOOR`: увеличить до 1,800 если exploit'ы через слабых, уменьшить до 1,200 если слишком строго
  - `CAP`: оставить 12,500 (совместимо с текущим регламентом GGL)
